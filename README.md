# Список задач

Веб-приложение в стиле Windows 95 на FastAPI, SQLAlchemy и PostgreSQL. Интерфейс серверный, интерактивность реализована на чистом JavaScript.

## Возможности

- Создание, редактирование, выполнение и удаление задач без перезагрузки страницы.
- Сохранение задач в PostgreSQL.
- Гостевой режим: задачи привязаны к текущему браузеру защищённой cookie.
- Регистрация и вход по логину и паролю.
- Перенос гостевых задач в аккаунт после регистрации или входа.
- Изоляция задач между пользователями.
- Личный кабинет с отображением логина, выходом на текущем устройстве и выходом на всех устройствах.
- Перемещаемые окна "Новая задача", "Список задач" и окна аккаунта.
- Сворачивание, разворачивание и закрытие основных окон, панель задач для их восстановления.
- Внутренний Windows-подобный скролл длинного списка.
- Адаптивное расположение и возврат окон в исходное состояние после входа, выхода и обновления.
- Пиксельный интерфейс Windows 95, иконка профиля и кастомный текстовый курсор.

## Безопасность

- Пароли хешируются `scrypt` с индивидуальной солью.
- Логины для отображения и названия задач шифруются AES-256-GCM.
- Для поиска логина хранится HMAC-SHA256, а не открытый текст.
- Сессии и гостевой идентификатор подписаны HMAC и лежат в `HttpOnly`, `SameSite=Lax` cookies.
- Каждая сессия хранится в таблице `user_sessions`: выход отзывает cookie на сервере, а "Выйти везде" завершает все сессии пользователя.
- В production cookies автоматически получают флаг `Secure`, а ответы - заголовок `Strict-Transport-Security`.
- Изменяющие запросы проверяются по `Origin` и Fetch Metadata.
- Есть ограничение размера тела запроса, общий лимит частоты запросов и отдельный, более строгий лимит на вход и регистрацию.
- IP клиента берётся из заголовков прокси только при `TRUST_PROXY_HEADERS=1` или при запуске на Railway, заголовки от клиента не учитываются.
- Число задач у одного владельца ограничено, гостевые задачи старше срока жизни гостевой cookie удаляются автоматически.
- Установлены CSP без внешних источников, `X-Frame-Options`, `X-Content-Type-Options` и `Referrer-Policy`.
- 95CSS и шрифт Press Start 2P раздаются с самого сервера, без CDN и Google Fonts.
- Повреждённая или не расшифровываемая запись показывается заглушкой и не роняет страницу.
- Production не запускается без постоянных `SESSION_SECRET` и `DATA_KEY`.

## Локальный запуск

Потребуются Python 3.12+ и PostgreSQL.

Создайте базу, например:

```bash
createdb todo
```

Установите зависимости:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
```

Настройте `.env`. Для локальной разработки достаточно:

```dotenv
DATABASE_URL=postgresql://todo:todo@localhost:5432/todo
APP_ENV=development
RATE_LIMIT=60
RATE_LIMIT_WINDOW=60
AUTH_RATE_LIMIT=10
AUTH_RATE_LIMIT_WINDOW=300
MAX_TASKS_PER_OWNER=500
SESSION_SECRET=local-development-secret
DATA_KEY=
COOKIE_SECURE=0
```

`DATA_KEY` в development можно оставить пустым: он будет получен из `SESSION_SECRET`. В production так делать нельзя.

Загрузите переменные и запустите сервер:

```bash
set -a
. ./.env
set +a
uvicorn app.main:app --reload
```

Приложение откроется на `http://127.0.0.1:8000/`. При старте оно применит только ещё не выполненные версии миграций из таблицы `schema_migrations`.

## Тесты

```bash
. .venv/bin/activate
pytest -q
```

Тесты используют отдельную временную SQLite-базу и не затрагивают PostgreSQL.

Чтобы прогнать те же тесты на PostgreSQL, укажите отдельную пустую тестовую базу. Перед каждым тестом её схема `public` пересоздаётся, поэтому рабочую базу сюда указывать нельзя:

```bash
TEST_DATABASE_URL=postgresql://todo:todo@localhost:5432/todo_test pytest -q
```

Проверка стиля и зависимостей:

```bash
ruff check .
ruff format --check .
pip-audit -r requirements.txt
```

В GitHub Actions (`.github/workflows/ci.yml`) на каждый PR и push в `main` запускаются ruff, pip-audit и тесты на SQLite и PostgreSQL 17.

## Переменные окружения

- `DATABASE_URL` - обязательный адрес PostgreSQL. Форматы `postgres://` и `postgresql://` автоматически преобразуются для psycopg.
- `APP_ENV` - `development` локально и `production` на сервере.
- `SESSION_SECRET` - секрет подписи cookies длиной не менее 32 символов в production.
- `DATA_KEY` - отдельный постоянный 32-байтовый ключ шифрования в hex или URL-safe base64. Hex-вариант содержит 64 символа.
- `COOKIE_SECURE` - необязательное переопределение: `1` включает Secure, `0` выключает. При `APP_ENV=production` Secure включён автоматически.
- `RATE_LIMIT` - число запросов с одного IP за окно, по умолчанию `60`.
- `RATE_LIMIT_WINDOW` - длина окна ограничения в секундах, по умолчанию `60`.
- `AUTH_RATE_LIMIT` - число попыток входа и регистрации с одного IP за окно, по умолчанию `10`.
- `AUTH_RATE_LIMIT_WINDOW` - окно для входа и регистрации в секундах, по умолчанию `300`.
- `MAX_TASKS_PER_OWNER` - максимум задач у одного пользователя или гостя, по умолчанию `500`.
- `TRUST_PROXY_HEADERS` - откуда брать IP клиента. `1`: из `X-Real-IP`, а без него из последнего адреса `X-Forwarded-For`. `0`: только адрес TCP-соединения. Если переменная не задана, заголовкам доверяют только на Railway (там есть `RAILWAY_PROJECT_ID`, а прокси Railway перезаписывает `X-Real-IP`), в остальных случаях не доверяют. Включайте `1` только за своим reverse proxy, который сам выставляет эти заголовки.
- `PORT` - порт Uvicorn.

Если сервис доступен напрямую по приватной сети Railway или через TCP proxy, задайте `TRUST_PROXY_HEADERS=0`: такие запросы идут в обход edge-прокси, и `X-Real-IP` в них может быть подделан.

Не меняйте `DATA_KEY` после появления данных: старые логины и задачи перестанут расшифровываться. Смена `SESSION_SECRET` завершит активные сессии.

## Обновления и база

Перед production-обновлением сделайте backup PostgreSQL. Миграции выполняются при старте под advisory lock, поэтому одновременные экземпляры не применяют одну миграцию параллельно.

Миграции:

- `001_current_schema` - базовая схема, шифрование логинов и задач.
- `002_user_sessions` - таблица `user_sessions` и колонка `users.session_version` со значением по умолчанию `0`. Старые cookie сессий продолжают работать до выхода или истечения срока, поэтому после обновления никого не разлогинивает.

При старте и не чаще раза в час удаляются истёкшие сессии и гостевые задачи старше 14 дней: к этому моменту гостевая cookie, которая их видела, уже истекла.

Для отката к версии приложения, которая не понимает новую схему, может потребоваться восстановление backup. Автоматического удаления колонок и данных нет.

## Структура

- `app/main.py` - маршруты FastAPI и операции с задачами и аккаунтом.
- `app/auth.py` - валидация, хеширование паролей, сессии и cookies.
- `app/cleanup.py` - удаление истёкших сессий и гостевых задач.
- `app/crypto.py` - шифрование и HMAC-индекс логинов.
- `app/db.py` - подключение SQLAlchemy и версионированные миграции.
- `app/security.py` - IP клиента, лимиты частоты, проверка Origin, лимит тела запроса и HTTP-заголовки.
- `app/templates/index.html` - разметка интерфейса, строка задачи описана одним макросом и для сервера, и для JavaScript.
- `app/static/` - стили, JavaScript и иконка. Ссылки на них содержат хеш содержимого, поэтому браузер кэширует их надолго и получает новую версию сразу после деплоя.
- `app/static/vendor/` - 95CSS и шрифт Press Start 2P вместе с их лицензиями.
- `tests/` - API, безопасность, владение задачами, сессии, лимиты и шифрование.
- `pyproject.toml` - настройки pytest и ruff.
- `.github/` - CI и Dependabot.
- `Dockerfile` - production-образ для деплоя.
