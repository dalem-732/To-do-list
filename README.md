# Список задач

Веб-приложение в стиле Windows 95 на FastAPI, SQLAlchemy и PostgreSQL. Интерфейс серверный, интерактивность реализована на чистом JavaScript.

## Возможности

- Создание, редактирование, выполнение и удаление задач без перезагрузки страницы.
- Сохранение задач в PostgreSQL.
- Гостевой режим: задачи привязаны к текущему браузеру защищённой cookie.
- Регистрация и вход по логину и паролю.
- Перенос гостевых задач в аккаунт после регистрации или входа.
- Изоляция задач между пользователями.
- Личный кабинет с отображением логина и выходом.
- Перемещаемые окна "Новая задача", "Список задач" и окна аккаунта.
- Сворачивание, разворачивание и закрытие основных окон, панель задач для их восстановления.
- Внутренний Windows-подобный скролл длинного списка.
- Адаптивное расположение и возврат окон в исходное состояние после входа, выхода и обновления.
- Пиксельный интерфейс Windows 95, иконка профиля и кастомный текстовый курсор.

## Безопасность

- Пароли хешируются `scrypt` с индивидуальной солью.
- Логины для отображения и названия задач шифруются AES-256-GCM.
- Для поиска логина хранится HMAC-SHA256, а не открытый текст.
- Сессии и гостевой идентификатор подписаны HMAC и лежат в `HttpOnly`, `SameSite=Lax` cookies.
- В production cookies автоматически получают флаг `Secure`.
- Изменяющие запросы проверяются по `Origin` и Fetch Metadata.
- Есть ограничение размера тела запроса и частоты запросов.
- Установлены CSP, `X-Frame-Options`, `X-Content-Type-Options` и `Referrer-Policy`.
- Production не запускается без постоянных `SESSION_SECRET` и `DATA_KEY`.

## Локальный запуск

Потребуются Python 3.12+ и PostgreSQL.

Создайте базу, например:

```bash
createdb todo
```

Установите зависимости:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
```

Настройте `.env`. Для локальной разработки достаточно:

```dotenv
DATABASE_URL=postgresql://todo:todo@localhost:5432/todo
APP_ENV=development
RATE_LIMIT=60
RATE_LIMIT_WINDOW=60
SESSION_SECRET=local-development-secret
DATA_KEY=
COOKIE_SECURE=0
```

`DATA_KEY` в development можно оставить пустым: он будет получен из `SESSION_SECRET`. В production так делать нельзя.

Загрузите переменные и запустите сервер:

```bash
set -a
. ./.env
set +a
uvicorn app.main:app --reload
```

Приложение откроется на `http://127.0.0.1:8000/`. При старте оно применит только ещё не выполненные версии миграций из таблицы `schema_migrations`.

## Тесты

```bash
. .venv/bin/activate
pytest -q
```

Тесты используют отдельную временную SQLite-базу и не затрагивают PostgreSQL.

## Переменные окружения

- `DATABASE_URL` - обязательный адрес PostgreSQL. Форматы `postgres://` и `postgresql://` автоматически преобразуются для psycopg.
- `APP_ENV` - `development` локально и `production` на сервере.
- `SESSION_SECRET` - секрет подписи cookies длиной не менее 32 символов в production.
- `DATA_KEY` - отдельный постоянный 32-байтовый ключ шифрования в hex или URL-safe base64. Hex-вариант содержит 64 символа.
- `COOKIE_SECURE` - необязательное переопределение: `1` включает Secure, `0` выключает. При `APP_ENV=production` Secure включён автоматически.
- `RATE_LIMIT` - число запросов с одного IP за окно, по умолчанию `60`.
- `RATE_LIMIT_WINDOW` - длина окна ограничения в секундах, по умолчанию `60`.
- `TRUST_PROXY_HEADERS` - задайте `1` только за доверенным reverse proxy.
- `PORT` - порт Uvicorn.

Не меняйте `DATA_KEY` после появления данных: старые логины и задачи перестанут расшифровываться. Смена `SESSION_SECRET` завершит активные сессии.

## Обновления и база

Перед production-обновлением сделайте backup PostgreSQL. Миграции выполняются при старте под advisory lock, поэтому одновременные экземпляры не применяют одну миграцию параллельно.

Для отката к версии приложения, которая не понимает новую схему, может потребоваться восстановление backup. Автоматического удаления колонок и данных нет.

## Структура

- `app/main.py` - маршруты FastAPI и операции с задачами и аккаунтом.
- `app/auth.py` - валидация, хеширование паролей и cookies.
- `app/crypto.py` - шифрование и HMAC-индекс логинов.
- `app/db.py` - подключение SQLAlchemy и версионированные миграции.
- `app/security.py` - защитные middleware и HTTP-заголовки.
- `app/templates/index.html` - разметка интерфейса.
- `app/static/` - стили, JavaScript и иконка.
- `tests/` - API, безопасность, владение задачами и шифрование.
- `Dockerfile` - production-образ для деплоя.
